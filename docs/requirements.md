# 项目背景与需求分析

## 使用场景

内网监测系统发出告警后，研判人员需要查找同一时段的终端日志，回答「哪台设备关联到这条告警」「有哪些可核查的迹象」「还缺哪些证据」。共享出口地址、设备时间差和缺失字段都会影响关联结论。

## 首版范围

- 批量导入脱敏或模拟的网络告警与 Windows Security Log、Sysmon 事件。
- 按来源、设备标识和时间范围查询。提供原始事件引用与规范化字段。
- 基于已知主机标识与时间窗口关联告警和事件。共享 IP 且缺少历史映射时记录为「归属待核查」。
- 助手基于候选证据生成事实、推测、证据缺口和待核查项。复核人员确认或驳回草稿并记录理由。
- 演示范围以离线流程为主。实时接入、NAT 历史映射和自动处置均列为后续评估事项。

## 验收条件

| 需求 | 预期行为 |
| --- | --- |
| 可重放的数据导入 | 同一批输入重复导入时保留一致的记录数量，错误记录可定位到来源 |
| 可回溯的告警关联 | 每条关联都有来源事件、规则或人工备注，缺失信息有明确状态 |
| 可审核的研判草稿 | 从结论可以打开引用的事件。无支持的引用被拒绝或标记为待核查 |
| 可审计的复核 | 记录复核人、时间、处理意见及对应草稿版本 |
